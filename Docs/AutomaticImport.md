# スクショの自動登録

## 画面と基本フロー

「スクショ取込」で画像をまとめて追加すると、全件のOCRが終わってから照合・検証・保存する。問題のない結果は登録ボタンを押さずに保存する。取込結果には自動登録・要確認・重複スキップ・失敗を分けて表示し、登録済み結果から履歴の編集・削除へ進める。

確認が必要な結果だけを一覧に残す。数値1項目が曖昧なら、その項目の推定値・実OCR候補・確認理由を表示する。曲候補だけが曖昧なら譜面を選択する。重複候補や複数の矛盾がある場合は、従来の全項目編集・既存履歴への統合を使う。

「高信頼結果を自動登録する」は初期状態でON。「環境・プリセット」でOFFにできる。分析画面はサマリー／タイミング調整／詳細データに分け、最初にプレイ数・FC/AP率・FAST/SLOWの偏りを表示する。

「楽曲・譜面」の個別譜面偏りは確認済みの全履歴を対象とし、設定が異なる履歴も含むことを表示します。そこから傾向分析へ移動すると、現在の環境・全設定に合う曲横断・プレイ時レベル別のタイミング候補を確認できます。候補条件と反対方向のレベル帯による保留は[固定タイミングの仕様](Timing.md)を参照してください。固定値の記録は傾向分析の環境上部から開き、ゲーム側で変更した確認を明示して保存します。

## 自動登録の条件

すべての条件を満たした場合だけ保存する。confidenceの合計点だけでは登録しない。

1. OCR由来の曲名候補と正規楽曲マスター・別名・難易度・Lvから、登録先の譜面を一意に決められる。大文字小文字、全半角、空白・記号、I/l/1・O/0・日本語の類似文字を考慮する。完全一致した曲名とLvが矛盾するときは、別曲へ自動変更しない。
2. スコア・コンボと、その画面に表示される判定数が取得できる。通常は総数5項目、詳細はFAST/SLOW各5項目、統合時は15項目。表示されない総数や未読取の値を生成しない。
3. 主要数値は競合する有力候補がなく、既定0.9以上の認識信頼度、または2画像の一致した根拠がある。変換後の画像だけで読めた6/9は元画像側の読取も必要。曲名はVisionのconfidenceが低くても、マスターと譜面情報で一意に確定できれば採用できる。
4. スコア・判定数・コンボが表示上の安全範囲内で、FAST＋SLOWが総数を超えない。通常・詳細が揃う場合、PERFECT以外の総数とFAST＋SLOWの差も確認対象にする。この検査で未読取値を補完しない。
5. FCはBAD/MISSが正なら不成立、APはGREAT以下が正なら不成立。全総数がある場合、FC/APのコンボと判定合計も照合する。GOODだけを理由にFCを否定しない。
6. マスターに`noteCount`があれば判定合計と必ず照合する。FC/APは詳細単独でもコンボを照合する。実OCR候補の組合せが総ノーツ数により一意に決まる場合は、低confidenceや数字の競合を解決できる。OCRで読めていない候補は作らない。
7. 既存履歴に同一結果の疑いがない。

`RegistrationAssessment.confidenceScore`は根拠の充足度を示す0〜100の指標で、正答確率ではない。曲名・難易度・Lv、数値、FC/AP、ノーツ数、日時、重複を個別に確認し、未解決の問題が1つでも残れば自動保存しない。日時不明だけでは問題扱いにしない。

## 通常・詳細の統合と重複

同じ正規譜面、スコア、コンボ、60秒以内の矛盾しない撮影日時があり、互いの組合せが1つだけなら通常・詳細を1プレイに統合する。達成表示や判定数の矛盾、組合せが複数ある場合は保留する。

既存画像とSHA-256が一致した場合は、OCRをせずにスキップする。異なる画像でも、同じ譜面・スコアに加えコンボまたは複数の判定数が一致する場合は既存履歴の候補として表示する。信頼できるプレイ日時が90秒以上離れている同値の結果は、別プレイとして扱える。日時がない場合は重複の判断を安全側に倒す。

日時がない通常・詳細を自動で1プレイにまとめることはしない。単独の結果はほかの条件を満たせば自動登録し、重複の疑いが生じた画像だけを確認する。

## 日時・環境・保存

既存のImageIOメタデータ／スクショ名の読取を利用する。候補が矛盾せず、未来などの不正値でなければ撮影日時をプレイ日時に採用し、取得根拠も保持する。日時不明・競合の場合は`playedAt = nil`、表示順には`importedAt`を使う。現在のリザルト配置には画面内のプレイ日時表示がないため、画面内日時のOCR追加は行っていない。

環境は取込開始時のスナップショットを使う。未設定のタイミングに0.10を補完しない。異なる設定画像を同時に取り込んだ場合は環境不明として保存し、設定を確認してから今回の履歴へ適用できる。過去の設定は変更しない。

永続化は既存の`ResultService`とSwiftDataを利用する。保存に成功してから状態を反映し、失敗時は確認待ち・既存履歴を保持する。追加項目は`Chart.noteCount`、`PlayRecord.registrationMethod`、`AppState.automaticRegistrationEnabled`のOptional。schemaVersionは1のままで、旧データの欠落項目を推測しない。

元画像・プレビュー・OCR全文・候補・信頼度・読取領域は実行中のメモリだけに保持し、保存payloadに追加しない。画像を変更せず、恒久アクセス権も保存しない。処理はMac内で完結し、macOS 26.4対応を維持する。自動判定はFoundation ModelsにもmacOS 27専用APIにも依存しない。

## 残る弱点

- 小さな6/9などは、Visionが高いconfidenceで誤読する。実画素を複数の領域で読み、競合が残る項目はユーザー確認とする。
- 同梱マスターには総ノーツ数が未収録。全譜面で総数との照合ができる状態ではない。出典確認済みの`noteCount`を追加すれば検証を強められる。
- 全読取が同じ誤値を返し、ほかの数値とも矛盾しない場合の誤認識を完全には排除できない。
- 同じ配置・縦横比の通常モード画面が対象。アシストモードや別レイアウトは自動登録しない。
- 実画像の検証率は提供された画像集合での実測であり、未知の端末・画面設定に対する精度保証ではない。
