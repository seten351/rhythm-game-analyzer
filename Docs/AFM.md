# Foundation ModelsによるOCR補助

## 役割

画像認識は引き続きApple Visionが行う。Foundation Models（AFM）は、Visionの結果に未読取・低信頼度・形式不正・曲名照合の曖昧さ・値の矛盾があるときに限り、OCR根拠から作られた許可候補のどれを採るか提案する補助機能である。AFMの応答だけで結果を登録せず、確認画面でユーザーが項目ごとに採用する。

## 候補と応答の制約

- 対象項目は曲名、難易度、レベル、スコア、コンボ、達成状態、判定総数、FAST、SLOW。
- 候補は当該画像のOCR結果、既存の検証済み数値パーサー、曲名に対する既存楽曲マスタ照合から作る。各項目に有限個の候補を与え、AFMの応答で候補を追加できない。
- 数値は同じ画像・項目のOCR根拠から厳密に読み取れたものだけを候補にする。楽曲マスタからプレイ時レベルを補ったり、FAST/SLOWから総数を計算したり、判定数からFC/APを推測したりしない。
- 実行時の生成スキーマで項目ごとに許可候補IDの列挙を定義する。各項目は省略／nullを許し、別項目のIDや同一項目の重複選択を構造上防ぐ。応答を項目IDと候補IDの組に変換し、既知の候補に属するかを決定的に検証する。未知ID、別項目の候補、重複項目など不正応答は採用しない。AFM自身の信頼度でVisionの信頼度を上書きしない。
- 未判断項目は未判断のまま残す。欠測値 `nil` と読み取ったゼロを区別する。

## 確認と保存

### 6/9判定曖昧

数値項目について、同じ画像・項目・領域から実際に読み取った候補が6と9の置換だけで異なり、その領域の最有力候補とのVision信頼度差がどちらも0.10以内なら「6/9判定曖昧」とする。複数桁の6/9や難易度領域のレベルも対象。別画像、別領域、別項目の数字は競合として扱わない。6/9を含むという理由だけで、未読取の反対候補を作らない。

通常の数値として読めていても、数値読取に6/9がある場合は単一候補でも既存の反転・拡大・余白付き再読取を行う。元の暫定値を保持し、元の読取と再読取を根拠として残す。再読取が単一候補でも、元の競合を黙って解消しない。許可候補は根拠にある6/9競合値に限定し、同じ値が複数回読めた場合も各読取の経路・信頼度をAFMに渡す。5候補を超える場合は候補の片側だけを残さず、AFM選択を行わず手入力へ戻す。

曖昧な各項目は、その項目だけを含む新規AFMセッションに分ける。他の判定数・合計・現在の暫定値は渡さず、整合による推測に使わせない。応答は許可IDの選択または省略だけ。選択があっても確定値とはせず、画像との照合と項目別採用、明示登録を必要とする。曖昧な根拠がある取込は自動登録対象から除外する。

アシスト表示を検出した画像は対応対象外として拒否し、AFM補助の対象にしない。FULL COMBOはGOODを許し、BAD/MISSが正なら矛盾とする。APはGREAT/GOOD/BAD/MISSが正なら矛盾とする。欠測の判定数をゼロへ補完しない。

### 項目別の確認

AFMはユーザーの明示操作で実行する。候補一覧では元の値、候補、根拠、画像上の該当箇所を確認できる。ユーザーが項目別に候補を採用すると編集欄に反映されるが、登録には従来どおり「確認して登録」の操作を要する。手入力値の採用をAFMで置き換えない。AFM実行や候補採用によって従来の確認待ち条件を緩めない。

AFMを使えない端末、Apple Intelligenceが無効、モデル未準備、言語非対応、生成拒否、期限切れの場合は理由を示し、Visionの解析結果を保ったまま既存の手動確認へ戻る。AFMの実行中に編集・統合・登録・破棄・画面終了が起きた場合は処理を中止し、遅れて返った応答を反映しない。

根拠、候補、指示、応答は処理中だけメモリに保持する。モデルの入力上限を事前に確認し、30秒で中止する。中止を受け付けてもモデル処理が終了するまでは次の生成を開始しない。履歴・SwiftData・ログへ保存せず、登録・破棄・終了時に解放する。既存の保存形式 `schemaVersion = 1` に変更を加えない。

## プライバシーと通信

Foundation Modelsは対応端末上でローカル実行する。アプリからAI API、外部API、クラウド、ネットワーク通信を追加しない。AFMには元画像、画像パス、履歴全体を送らず、候補選択に必要なOCR根拠と候補だけを渡す。外部パッケージも追加しない。
