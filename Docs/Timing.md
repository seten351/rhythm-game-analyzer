# 固定ノーツタイミングと調整候補

ノーツタイミングはプレイ環境ごとの固定値として保持します。設定スクショは毎回不要です。2026-10-02のユーザー指定により、端末はM2 iPad Pro 11インチに固定し、スピーカー／イヤホンの違いは記録用として扱います。遅延の推定・補正は行いません。

## 確認と保存

初回は「環境・プリセット」の「タイミングを確定…」、または新規リザルト登録時にゲームの値を入力して確定します。ユーザー確認済みの現在値0.10を初回入力の候補にしますが、保存するまで設定や履歴に反映しません。すでに固定値があればそれを優先します。

高信頼の結果は確認画面を出さず、取込開始時の環境と固定値をスナップショットとして保存します。未設定ならnilを維持し、0.10を自動補完しません。異なる設定スクショが同じバッチにある場合は環境不明で登録し、確認後に今回の履歴へ適用できます。

全項目の手動確認画面では、従来の選択を利用できます。

- 変更していない：固定値をプレイのスナップショットへ保存。
- 変更した：入力値を今回のプレイと今後の固定値へ1回の保存で反映。保存失敗ならどちらも更新しない。
- 今回の値は不明：今回だけタイミングnilにし、固定値は維持。環境不明の場合も推測しない。

問題のある項目だけの確認画面では、固定値をそのまま引き継ぎます。保存済みプレイへ追加画像を統合する場合は、そのプレイの過去の設定（不明も含む）を保持します。履歴の明示編集・任意設定画像のバッチ適用は既存の機能として残します。読めなかった設定画像のタイミングnilで固定値を消しません。

固定値専用UIでは「ゲームでこの値に設定したことを確認しました」を選択して保存します。アプリはゲームを操作しません。開いた時から環境・固定値が変わっていた場合は保存を拒否し、再確認を求めます。一般環境編集はタイミングを上書きしません。

## 調整候補

「楽曲・譜面」の個別譜面パネルには、確認済みの全履歴のFAST/SLOW偏りを表示します。異なる設定の履歴も含む全体値なので、その旨とプレイ数・詳細数を併記し、「傾向分析でタイミングを確認」から現在の設定に合わせた候補へ移動できます。

「傾向分析」のタイミング調整タブは、選択中の環境IDと4つの設定値（速度・タイミング・譜面位置・ミラー）に一致する確認済み履歴を使います。同一ゲームの既知譜面に対応し、PERFECT＋GREATのFAST/SLOW詳細4値が既知で、その合計が正の履歴が対象です。アワーノーツの固定端末ポリシーでは既知の端末名別名と旧履歴の端末名空欄を許容し、音声出力・条件メモをまとめます。厳格ポリシーでは端末・音声出力・条件も一致させます。

対象履歴は譜面ごとに`orderDate`（`playedAt ?? importedAt`）の降順で最大10プレイ選び、同時刻はUUID文字列の昇順で決めます。選択は一度だけ行い、全体集計と`levelAtPlay`別の集計に同じ履歴を分けて使います。レベル不明の履歴は全体へ含め、不明グループにも表示しますが、そのグループに数値候補は出しません。

端末名が空欄の旧履歴は、今回ユーザーが確認した固定端末として集計時だけ解釈します。固定端末名の既知表記も対象にしますが、別端末が明記された履歴は除外します。起動時や候補表示時に保存データを書き換えません。今後の環境保存・タイミング確定・設定画像適用・新規登録では固定端末名を記録します。既存プレイの追加画像統合は当時のスナップショットを保持します。汎用コアは既定で従来の厳格な端末・音声・条件一致を維持し、この扱いはアワーノーツに明示適用します。

- 異なる3曲以上。別難易度・複数譜面を同じ曲として数え、反復プレイで曲数は増えません。
- P＋GのFAST/SLOW詳細が合計500件以上。
- 各曲内では詳細件数で偏りを計算し、曲ごとの偏りを曲あたり同じ重みで平均します。その絶対値が10%以上で、詳細件数で加重した全体偏りも同じ方向であること。
- 3分の2以上の曲で偏りの方向が一致します。方向がゼロの曲もこの割合の分母に含めます。
- 速度・タイミング・譜面位置・ミラーが入力済み。欠測値を推測しない。設定スクショでの入力も従来通り使用可能。
- 現在値と1ステップ後の値が仕様の範囲・刻みに合う。

条件を満たせば1ステップだけ試す候補を提示します。SLOW優勢なら0.10→0.11、FAST優勢なら0.10→0.09など。最適値や正確な遅延時間を断定しません。詳細画面では曲ごとの偏りと、詳細件数で加重した偏りを並べて根拠となった曲も確認できます。

十分なデータがあるレベル帯同士で候補方向が逆、または候補を出せる全体傾向とレベル帯の方向が逆なら、全体の変更候補を保留します。データ不足・維持・仕様未確認のレベル帯は逆方向の根拠として扱わず、全体候補を止めません。各レベル帯の候補はそのレベルを中心に試す際の参考で、保存する固定値は環境ごとに1つです。

候補を実際に記録する場合は、傾向分析の現在環境上部にある「ゲームで変更した値を記録する…」を使います。入力値をゲーム側で設定したことの確認が必須です。アプリはゲームを操作しません。表示だけでは固定値・履歴を変更せず、保存後は新しい固定値に一致する履歴で再計測します。

## 仕様の根拠

2026-10-02のユーザーによるゲーム画面の確認：変更刻み0.01、初期値0、範囲−3〜3、現在値0.10、SLOWが多い場合は値を上げ、FASTが多い場合は下げる。同梱プリセットv2に反映しました。単位はミリ秒と確認できていないため「ゲーム内単位」と表示します。

先に依頼されたWeb調査では、[公式サイト](https://bang-dream-on.bushimo.jp/)と[プレイヤーの判定調整記事](https://note.com/nanagi485/n/n66eb6a2c2c7a)を確認対象にしましたが、刻み・上下限・増減方向・単位を一式で確定できませんでした。実装値の根拠はその後のユーザー回答です。他ゲームの仕様やノーツ速度の刻みは転用しません。ゲーム側の仕様変更があれば版を増やして更新します。

旧インポートOCRプリセットにtiming仕様がない場合も、アワーノーツに限り同梱の確認済み仕様を使います。明示的なインポート仕様があれば優先します。保存形式は既存のPlayEnvironment／PlayRecordスナップショットで、schemaVersionは1のままです。
