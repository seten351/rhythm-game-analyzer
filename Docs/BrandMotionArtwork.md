# ブランドモーションと楽曲画像

改訂Planの実装境界。「アワーノーツ・ロゴ（ブランド）」でのみモーション・楽曲画像を表示する。既存テーマ、履歴モデル、DBスキーマ、OCR、分析用JSONの形式は維持する。

## モーション

| 対象 | 時間と動作 |
| --- | --- |
| サイドバー／タブ／達成フィルター | easeOut 0.16秒、選択アクセントを移動 |
| 譜面一覧 | easeOut 0.16秒、固定行の背景と短いアクセントをクロスフェード |
| タブ本文 | 選択キーの変更時だけ0.16秒のフェード |
| 新規成果 | ライン0.22秒。0.08秒後からカードを0.20秒でfade＋8pt移動＋scale 0.98→1。合計0.28秒 |
| プレイ詳細 | 開く0.16秒、閉じる0.14秒。暗転とfade＋scaleを同期 |
| 空状態 | 小さいマークのフェード。保存履歴が0件→1件以上になった境界だけ本文0.16秒 |
| 最高スコア／最大コンボ | 同じ譜面の増加だけ操作色を0.12秒で重ね、0.16秒で通常色に戻す |

Reduce MotionはOS設定と検証スイッチのOR。移動・scale・ライン再生・数字の強調を止め、必要なopacityだけ最大0.12秒にする。フィルター／選択／初期表示だけでは数字や保存境界の演出を発火しない。成果のセッション台帳は保存成功した今回のplayIDだけを一度表示する。ホバー、スクロール、画面全体、一般ボタンに追加モーションを付けない。

## 詳細オーバーレイ

RootViewのブランドテーマだけに置く。540pt幅、画面高さ以内の内部スクロール。背景クリック・Escape・閉じるボタンを同じ閉じる処理へ集約し、内容内クリックでは閉じない。閉じるフェードが完了するまで背景のヒットを遮断し、履歴への移動も完了後に実行する。

SwiftUIのFocusState／AccessibilityFocusState、focusSection、cancelAction、FocusedValuesを利用する。背景はdisabled＋accessibilityHiddenにし、取込コマンドも無効化する。Tabは詳細内の標準順序で移動し、閉じた後は起点の成果／最近のプレイへ戻す。AppKitは必要な既存firstResponderの保存／復元だけ。新しいキー監視は追加しない。従来テーマはネイティブシート、履歴編集と設定フォームも従来のシートを維持する。

## ArtworkKeyと画像保存

ArtworkKeyはCatalogBindingの `(gameID, sourceID, externalID)`。ローカル曲UUIDや曲名はファイル名にしない。同梱マスター生成処理が既存外部IDを継承し、OurNotesCatalog.installが対応UUIDを維持／統合することを確認した。UUIDはアーカイブ曲がbindingを失った場合の旧対応だけに使う。現行曲のbindingが不明／競合ならプレースホルダーと登録不可にする。

通常の保存先はサンドボックスのApplication Support/OurNotesAnalyzer/Artwork。索引はキー・不変asset UUID・関連曲UUIDだけ、画像は `images/<assetID>.png`。元パス、元ファイル名、EXIF、位置情報、ブックマークを保存しない。入力はPNG／JPEG／HEIC、80MB・最大辺20000pxまで。向きを適用し、最大辺512pxのPNGへピクセルだけを再エンコードする。ユーザーの明示指示により、2026-10-04にWiki*の85曲のジャケットを既定画像として追加した。アプリ実行時にネットワーク取得は行わない。

actorが保存・回収を直列化する。各保存領域は同じSongArtworkStoreを共有する。

1. 同じファイルシステムへ一時画像を書き、同期・検証する。
2. 不変assetIDの画像へ移動する。
3. 旧索引の正常な復旧コピーを保持し、新索引を一時ファイルへ書き、同期・検証する。
4. 同じディレクトリ内のrenameで索引を原子的に置換する。この時点が確定点。
5. 確定後にUI索引を更新し、assetIDをキーにしたメモリキャッシュを無効化する。
6. 復旧索引を新しい確定世代に進めてから、旧画像をゴミ箱へ回収する。ここで失敗しても保存成功を取り消さない。

画像／索引の途中失敗では旧画像・旧索引を失わない。復旧索引更新が失敗した場合は旧世代の画像を残す。索引のprimaryが壊れた場合は正常backupから復旧する。両方壊れた場合は、管理名に一致する画像・索引をゴミ箱へ退避し通知する。未知のファイルやシンボリックリンクは回収しない。

起動時の同梱マスター適用成功後、画像操作の成功後、曲／bindingの状態保存成功後に整合性を確認する。アーカイブ曲は保持し、曲が実際に消えた／画像参照が失われた／管理画像が壊れた場合は索引を修復して未参照ファイルをゴミ箱へ移す。回収失敗は通知して次回起動で再試行する。画像を削除してもプレイ履歴は変更しない。

画像フレームは一覧36pt、譜面詳細72pt、プレイ詳細64pt、最近36pt、成果48pt。曲名・譜面・数字は画像の外に置く。手動画像→同梱ジャケット→共通の静かなノーツラインの順に表示する。同梱画像がない／読込不可の場合も曲名・数値を保持する。

## 同梱ジャケット

`Resources/Artwork/manifest.json` がArtworkKeyとハッシュ名PNGを1対1で対応付ける。曲名やローカルUUIDを読込キーにせず、手動画像と同じカタログbindingを使う。元画像はピクセルだけを最大辺512pxのPNGへ変換し、出典URL・元ファイル名・取得日・元／変換後SHA-256をmanifestへ記録した。対象一覧の85曲すべてを照合し、新曲「過去を喰らう」は既存84曲・336譜面のIDを保持したマスターrevision 2で追加した。

同梱領域は読取専用で、手動画像の索引・原子的保存・復旧・孤児回収へ混ぜない。「既定の画像に戻す」は手動overrideだけを削除する。手動画像の更新／削除で手動キャッシュを無効化し、同梱キャッシュは独立して保持する。同梱側はファイル名＋SHA-256でキャッシュし、読込時にサイズ・PNG形式・ハッシュを検証する。manifest重複・パストラバーサル・壊れた画像は表示しない。出典は[SongArtworkSources.md](SongArtworkSources.md)を参照。

## 検証

保存・回収の自動テストは人工PNGと一時保存領域だけを使う。複合キー、UUID再対応、アーカイブbinding消失、現行binding競合、各確定前失敗の旧バイト保持、primary／両索引破損、孤児回収・回収失敗再試行、キャッシュ置換／削除、状態DB保存失敗時の画像保持を確認する。同梱画像は85曲のキー対応・復号・ハッシュを読取専用で検証する。

実画面は別Bundle ID＋メモリ履歴の検証アプリを使う。手動画像は自作画像、既定画像はユーザー指定のWiki掲載画像を使用する。通常DBを開かず、ライト／ダーク、Reduce Motion、画像あり／なし、背景／内側／Escape／ボタン、Tabと起点への復帰、一覧矢印キー、タブ、従来テーマとシートを確認する。結果と実機・監査の範囲はVerification.mdに記録する。
