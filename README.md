# Rhythm Game Analyzer

音ゲーのリザルト解析・プレイ記録・傾向分析を扱うローカルmacOSアプリのプロジェクトです。現在はアワーノーツ向けの「Our Notes Analyzer」を実装しています。今後ほかの音ゲーにも対応を広げられるよう、リポジトリ名は `rhythm-game-analyzer` としています。

アワーノーツのリザルトをApple Visionで解析する、SwiftUIのローカルmacOSアプリです。曲名・難易度・Lvを正規マスターに照合し、数値の整合性を検証して、問題のない結果を自動登録します。確認が必要な項目だけを表示します。自動判定はFoundation Modelsに依存せず、AI API・外部API・クラウド・外部パッケージを使用しません。

Gitではソース、同梱マスター・プリセット、テスト、ビルドスクリプト、設計・検証資料を管理します。`photo/` の元画像、書き出したプレイ履歴JSON、`Docs/PlayAnalysis*.md` の個人成績レポート、ローカルDB、認証情報、`dist/` とビルド生成物は含めません。実画像による検証には手元の画像を用意してください。

## 起動

通常モードが対象で、アシストモードは対応対象外です。FULL COMBOはGOODを含んでも成立し、BAD/MISSの正の判定数がある場合に矛盾とします。ALL PERFECTはGREAT/GOOD/BAD/MISSの正の判定数がある場合に矛盾とします。欠測値はゼロに置き換えず、読取不足は確認待ちにします。

6/9などの有力な数値候補が競合すると、その項目を確認待ちにします。マスターに総ノーツ数があり、OCRで実際に読めた候補の組合せが一意に決まる場合は、自動で解決できます。未読取の値や表示されていない総数は推測しません。既存のFoundation Models補助は手動確認画面で任意に使用でき、候補の明示採用が必要です。

最低対応OSはmacOS 26.4です。ビルドにはCommand Line Tools単体ではなく完全版Xcodeが必要です。複数のXcodeがある場合は、このシェル実行に限って `DEVELOPER_DIR` を指定できます。

```sh
DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer" bash Scripts/build-app.sh
# または、xcode-selectで選択済みの完全版Xcodeを使用
bash Scripts/build-app.sh
open "dist/Our Notes Analyzer.app"
```

`DEVELOPER_DIR` はスクリプト内でプロセス環境として利用し、システム全体の `xcode-select` 設定は変更しません。Command Line Toolsが選択されている場合は日本語のエラーを表示します。

生成アプリはApp Sandboxを有効にしたローカル用のアドホック署名です。ネットワークの送受信権限を含みません。`Package.swift`をXcodeで開いて開発することもできます。Foundation Modelsが利用できない場合も、Visionによる自動登録と手動確認を利用できます。macOS 27専用APIは使いません。

## 最初の使い方

1. 起動するとWeb照合済みの全曲マスター（2026-10-02時点で84曲・336譜面）が自動登録されます。楽曲の手動登録・JSONの選択は不要です。既存マスターと手修正値は正規データへ置き換え、プレイ履歴は保持します。
2. 「環境・プリセット」で速度・譜面位置・ミラーを入力し、「タイミングを確定…」からゲームの現在値を一度記録します。端末はM2 iPad Pro 11インチ固定、音声出力はスピーカー／イヤホンの任意記録です。遅延の推定・補正は行いません。初回の入力候補はユーザー確認済みの0.10で、保存するまで確定しません。不明なら空欄にできます。
3. 「スクショ取込」で通常・詳細リザルトをまとめて選択します。全画像の解析後、安全に一意確定した結果を自動登録します。通常・詳細の曲・スコア・コンボが一致し、撮影日時が60秒以内で組が一意なら1プレイに統合します。
4. 「今回の取込結果」に自動登録・要確認・重複スキップ・失敗件数を表示します。数値の未読取や競合は、問題のある項目だけ確認します。自動登録済みの結果も、ここから編集・削除できます。
5. 自動登録では、取込開始時の環境と固定タイミングを引き継ぎます。不明値は不明のままです。ゲーム設定を変更したときは、取込前に固定値を更新してください。異なる設定画像を同時に取り込んだ場合は環境不明で登録し、設定確認後に今回の履歴へ適用できます。
6. 「傾向分析」はサマリー・タイミング調整・詳細データの3タブです。タイミング調整では現在の環境・全設定に一致する履歴を曲横断とプレイ時レベル別に集計します。個別譜面の偏りは確認済みの全履歴を使い、設定が異なる履歴を含むことを表示します。候補を保存する場合は環境上部のボタンから進み、ゲームで値を変更した確認を明示します。
7. 「楽曲・譜面」は譜面ごとの比較表です。曲名・別名、難易度、Lv、達成状況で絞り込み、記録日・曲名・Lvで並べ替えられます。選択した譜面の右側で概要／履歴を切り替え、編集・削除や傾向分析へ進めます。最高スコアは全環境・全設定の記録を対象とし、達成不明と未プレイは区別します。未FC・未APには両方を含みます。アーカイブ表示は一覧の「…」メニューから切り替えます。

自動登録は初期状態でONです。「環境・プリセット」で切り替えられます。判定条件と確認が必要なケースは [自動取込の仕様](Docs/AutomaticImport.md) を参照してください。

## 成果ホームと配色

起動時は「成果ホーム」を表示します。今回登録したプレイから、初AP・初FC・同一譜面の最大コンボ更新を優先して1譜面1件表示します。再起動後は最近登録した20プレイが対象です。ホームにはスコアを表示せず、最大コンボ、PERFECT率、FC/AP達成譜面数を表示します。カードから判定詳細や既存の譜面履歴へ進めます。

初達成や更新は保存された確定履歴の範囲で判断し、異なる環境・設定も含みます。登録日時を基準にしており、過去のスクショを新しく取り込んでも今日プレイしたとは扱いません。最大コンボの過去値が不明なら更新とは判定せず、不明値は「—」で表示します。PERFECT率は全5判定の総数が既知かつ合計が正の場合だけ計算します。

「環境・プリセット」上部で、配色と表示モードを別々に選べます。どちらも次回起動時に保持します。

- **配色**：標準／アワーノーツ風／アワーノーツ・ロゴ／アワーノーツ・ロゴ（ブランド）。プレビューを押して切り替えます。既存の3配色は比較用に保持しています。
- **表示モード**：システムに合わせる／ライト／ダーク。ライトとダークはMacの外観設定に関係なく固定します。

従来の「アワーノーツ風」は、提供スクショに加えて[公式サイト](https://bang-dream-on.bushimo.jp/)と[ゲーム紹介](https://bang-dream-on.bushimo.jp/system/)を参考にした、白紫／深い紺と青紫・シアン・ピンクの配色を保持しています。「アワーノーツ・ロゴ」は、追加で提供されたロゴの青灰・水色・くすんだピンクと、右上へ重なる帯を取り入れています。サイドバーと成果カードに線のモチーフを使い、本文は落ち着いた面に表示します。いずれも公式の厳密な指定色の再現ではなく、解析画面の読みやすさに合わせた配色です。実行時のWebアクセスや画像ダウンロードは追加していません。

追加の「アワーノーツ・ロゴ（ブランド）」は、青灰の面・短い3色の斜線・細いスクリプト英字を共通化した比較案です。APはくすみピンク、FCと操作は水色、未プレイ・達成不明はグレーで区別します。淡いロゴ色は装飾に使い、ライトの文字・ボタンにはコントラストを確保した濃い色を使います。サイドバーと一覧の選択は薄い水色で、グラフのデータ色は別に維持します。英字はmacOSのSnell Roundhandを優先し、Apple Chancery、Noteworthy Light、システムのセリフ体イタリックの順にフォールバックします。曲名・数値・日本語UIはシステムフォントを維持し、フォントや画像の追加ダウンロードは行いません。

ブランドラインは、画面の開始と特別な成果に3本、通常見出し・空状態には青灰と水色の2本を使います。成果カードはAP／FC／コンボ更新の主役色を線の長さでも区別し、英字は小さなカテゴリ表記に限定します。検索結果なし・未プレイ・記録ゼロ・取込前も同じ控えめな空状態を使い、日本語の説明と既存の操作を維持します。

## 保存する情報

解析値、固定ID、自動／手動の登録区分、判定の確認状態、設定スナップショット、プリセット版、日時、SHA-256、結果領域の64bit知覚ハッシュをローカルSwiftDataに保存します。OCR補助の根拠や候補は処理中だけメモリに保持し、履歴・保存payloadへ追加しません。元画像やサムネイル、全文OCR、ファイルへの恒久アクセス情報は保存しません。確認画面の画像はメモリ内だけで保持し、登録・破棄・終了時に解放します。元画像は変更しません。

署名アプリの保存先はサンドボックスコンテナ内のApplication Supportです。正確な保存先は「環境・プリセット」に表示します。保存失敗時はメモリ上の状態も更新せず、既存DBを上書き初期化しません。

## マスタとプリセット

- [マスタファイル仕様](Docs/CatalogFormat.md)：固定ID、完全／部分更新、照合、外部収集ツールとの契約。
- [プリセット仕様](Docs/PresetFormat.md)：読取領域とタイミング仕様の版管理。
- [Gamerch](https://gamerch.com/bang-dream-on/993622)、[AppMedia](https://appmedia.jp/bang-dream-on/80416189)、[データベースWiki](https://wikiwiki.jp/on_database/楽曲一覧)を照合した全曲データを同梱。アプリ更新後の起動時に自動適用します。
- マスターの手修正と手動取込は行いません。OCR未照合曲は新曲として作らず、読取値の修正または正規譜面の選択を求めます。
- 開発側のデータ更新は `/usr/bin/python3 Scripts/update_catalog.py` でWebから自動収集します。曲ごとの出典と競合の採用結果も保存。アプリ本体はWebへアクセスせず、定期更新は行いません。
- 同梱プリセットv2はユーザー確認済みのタイミング仕様を持ちます。0.01刻み、−3.00〜3.00、SLOW優勢は増加・FAST優勢は減少。「ゲーム内単位」と表示し、ミリ秒に換算しません。旧OCRプリセットで仕様が空の場合も、この確認済み仕様を使います。
- [固定タイミングと調整候補](Docs/Timing.md)：確認・保存・提案条件と仕様の根拠。

## 統計

各判定率は全5判定の総数が既知のプレイをノート数で加重します。FAST/SLOW比率はPERFECT＋GREATの詳細件数を分母にします。FC/AP率は達成状態が既知のプレイが分母で、APはFCにも含めます。欠測値はゼロにしません。対象件数と、スコアの平均・中央値・標本標準偏差・最小・最大を表示します。レベル変更後も履歴のプレイ時レベルを保持します。

曲横断のタイミング候補は譜面ごとに直近10件を選び、その同じ履歴を全体と`levelAtPlay`別へ分けます。異なる3曲以上、詳細500件以上、曲ごとの偏りの平均が10%以上、詳細件数で加重した偏りと同じ方向、かつ3分の2以上の曲が同方向の場合に限り、1ステップ候補を表示します。同じ曲の複数譜面は1曲です。逆方向の十分なレベル帯があれば全体候補を保留し、レベル不明群は全体には含めますがレベル別候補を出しません。[固定タイミングと調整候補](Docs/Timing.md)

## 検証

```sh
DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer" swift test --disable-sandbox
swift run --disable-sandbox OurNotesAnalyzer --verify-storage
swift run --disable-sandbox OurNotesAnalyzer --verify-images /path/to/result.png /path/to/detail.png
```

提供された7枚専用の通し検証は、`--verify-workflow`の後に7ファイルのパスを指定します。通常DBを変更せず、バッチ取込・ペア統合・重複除外・集計・一時DBの再読込を検証します。`--show-verification`も指定すると、検証結果をメモリ上だけでアプリに表示します。終了すると確認用データは失われます。

AFMの人工OCRによる実モデル検証は `--verify-afm`、保存しない確認画面は `--show-afm-verification` で起動します。実画像7枚の通し検証にAFMを含める場合は、`--verify-workflow --verify-workflow-afm` に続けて7ファイルを指定します。AFMが利用可能なら許可候補IDと「解析値・登録データを自動変更しない」ことを確認し、利用不可なら理由を表示してAFM部分をスキップします。これらの検証は通常DBへ保存しません。

自動登録の実画像検証は `--verify-auto-import` に画像パスを続けて指定します。通常DBに触れず、OCR・一括照合・保存・同画像の再取込・ディスク再読込・元画像が変わらないことを検証します。`--show-auto-import-verification` の併用で結果を一時的にUIへ表示できます。

[実施した検証と残る確認事項](Docs/Verification.md)

人工6/9候補の実モデル検証・確認画面には、それぞれ `--verify-afm --six-nine-fixture`／`--show-afm-verification --six-nine-fixture` を使います。OCRの実精度検証とは区別し、候補の省略も手動確認への正常な結果として扱います。

[Foundation ModelsによるOCR補助の設計と制約](Docs/AFM.md)

タイミング提案UIの人工履歴による確認は `--show-timing-verification` で起動できます。通常DBへ保存せず、最適値の実測検証には数えません。

楽曲一覧のUI確認は `--show-library-verification` で起動できます。同梱マスターにAP・FC・達成不明・欠測・複数環境の人工履歴を加え、メモリDBだけを使います。検証専用のBundle ID末尾が `.library.verification` の場合も同じデータを表示します。通常アプリのDB形式と保存済み履歴は変更しません。

成果ホームのUI確認は `--show-home-verification`、空の状態はさらに `--home-empty` を指定します。検証用Bundle ID末尾 `.home.verification`／`.home.empty.verification` も同じ入口です。`.home.light.verification` は「システムに合わせる」のときだけライト環境を模擬します。明示したライト／ダークの選択が優先され、Mac全体の設定は変更しません。すべてメモリDBを使用し、通常の保存履歴を開きません。

画像検証は指定された元画像から直接実行し、正規化した解析値だけを標準出力へ返します。画像をリポジトリにコピーしません。サンドボックス署名アプリの入力はファイル選択またはドラッグ＆ドロップを使います。

初期対応は提供画面と同じ配置・縦横比のスクショです。別レイアウト、画面の撮影写真、画像からの正確な遅延時間推定、外部収集の定期実行は初期対応に含みません。

## 外部エージェント用JSONとスクショ日時（v0.2.0）

「傾向分析」の「書き出す」メニューから、全楽曲・譜面マスターと保存済みの確定プレイ履歴を1ファイルに出力できます。画面の絞り込みに関係なく全履歴を対象とし、当時の環境・設定、判定、FAST/SLOW、日時と取得根拠、アプリ版・出力形式版・分析ルール版を含めます。不明値は`null`、既知のゼロは`0`です。画像、画像名・パス、画像指紋、OCR途中データは出力しません。集計方法とCodex／Antigravity向けの分析依頼文は [分析用JSON形式](Docs/AnalysisExportFormat.md) を参照してください。

取込時はEXIF・XMP・IPTCの撮影／作成日時を読み、有効なメタデータがなければ `screenshot_YYYYMMDD_HHmmss_SSS.png` 形式のファイル名を使います（JPEG／HEICも同形式）。タイムゾーンがない日時は日本時間として解釈したことを表示します。自動登録では矛盾のない撮影日時をプレイ日時に採用します。日時だけ不明・競合の場合は登録を止めず、プレイ日時をnilのままにして表示順に登録日時を使います。両者と取得元は区別し、履歴編集で変更できます。通常／詳細の統合後も画像ごとの匿名IDと正規化済み日時根拠を保持します。追加画像の統合は既存プレイ日時・当時設定を保持し、日時根拠だけを追記します。ファイルシステムの作成・更新日時は撮影日時として使いません。

保存DBはschemaVersion 1のまま、日時根拠をOptional項目で追加しています。旧履歴の日時や環境は推測して補完しません。JSON保存用にユーザー選択ファイルの読取・書込権限を使い、ネットワーク権限は追加していません。

開発用の `--verify-analysis-export` に `photo/` の59画像を渡すと、59枚の日時取得、実画像7枚のOCR・3組の統合、JSON出力、統計、重複除外、使い捨てDBの再読込を検証します。`--show-export-verification` を併用するとメモリ上の検証データと未登録画像をUIに表示します。通常DBは変更しません。
